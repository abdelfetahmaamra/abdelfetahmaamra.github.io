# رونق الحياة — المنصة الكاملة (Convex)

متجر بالدفع عند الاستلام + لوحة تحكم لإدارة الطلبات والتوصيل، مبنية على **Convex** (قاعدة بيانات + خادم) مع ربط **Yalidine / ZR Express / NOEST / EcoTrack** و **Meta Conversions API**.

```
ronaq/
├── convex/          الخادم وقاعدة البيانات (TypeScript)
│   ├── schema.ts        الجداول
│   ├── orders.ts        الطلبات ومسار التأكيد
│   ├── dispatch.ts      الإرسال لشركات التوصيل + المزامنة
│   ├── lib/carriers/    Yalidine, ZR Express, NOEST, EcoTrack
│   ├── meta.ts          Meta Conversions API
│   ├── http.ts          واجهة المتجر العامة (/api/…)
│   └── crons.ts         مزامنة حالات الطرود كل 30 دقيقة
├── src/             الموقع بـ React + Vite
│   ├── store/           المتجر: الرئيسية، المنتج، السلة، الشكر، استمارة الطلب
│   ├── admin/           لوحة التحكم (/admin) — تُحمَّل منفصلة عن المتجر
│   └── styles/          التصميم (CSS)
├── public/data/     الولايات والبلديات
├── .env.production  ← روابط Convex لنسخة الإنتاج (الملف الوحيد الذي تعدّلينه للربط)
└── tests/           اختبارات الخادم
```

---

## 1. التشغيل لأول مرة (حوالي 20 دقيقة)

تحتاجين **Node.js 20** أو أحدث على جهازكِ (nodejs.org).

```bash
cd ronaq
npm install
npm run dev             # يشغّل Convex والموقع معاً على http://localhost:5173
```

اتركي هذه النافذة مفتوحة، فهي ترفع الكود إلى Convex عند كل تعديل، وتحدّث الموقع فوراً. المتجر على `http://localhost:5173` ولوحة التحكم على `http://localhost:5173/admin`. ثم في نافذة ثانية:

```bash
npx convex run maintenance:seed
npx convex run authNode:createOwner '{"email":"you@example.com","name":"إسلا","password":"كلمة-سر-طويلة-جداً"}'
```

- الأمر الأول يضيف الفئات و8 منتجات أمثلة، وتعدّلينها لاحقاً من لوحة التحكم.
- الأمر الثاني ينشئ حساب المالك. كلمة السر 10 أحرف على الأقل.

## 2. ربط الموقع بـ Convex

- **على جهازكِ:** لا شيء لتفعليه. `npm run dev` يكتب الروابط في `.env.local` ويستعملها الموقع تلقائياً.
- **للإنتاج:** من لوحة Convex (نسخة Production): **Settings › URL & Deploy Key**. انسخي رابطين وضعيهما في `.env.production`:

| الرابط | ينتهي بـ | المتغير |
|---|---|---|
| Deployment URL | `.convex.cloud` | `CONVEX_URL` |
| HTTP Actions URL | `.convex.site` | `CONVEX_SITE_URL` |

لا تضعي أبداً مفتاح النشر (Deploy Key) في هذا الملف.

## 3. مفاتيح شركات التوصيل و Meta

في لوحة Convex: **Settings › Environment Variables**. أضيفي فقط ما تستعملينه:

| الشركة | المتغيرات | من أين |
|---|---|---|
| **Yalidine** | `YALIDINE_API_ID`, `YALIDINE_API_TOKEN` | لوحة Yalidine › Développement / API |
| **ZR Express** | `ZR_API_KEY`, `ZR_TENANT_ID` | لوحة ZR Express (المنصة الجديدة) › API |
| **NOEST** | `NOEST_API_TOKEN`, `NOEST_USER_GUID` | لوحة NOEST › API |
| **EcoTrack** (DHD, Conexlog…) | `ECOTRACK_BASE_URL` (مثال `https://dhd.ecotrack.dz`), `ECOTRACK_TOKEN`, اختياري `ECOTRACK_NAME` | لوحة الشركة › API |
| **Meta** | `META_ACCESS_TOKEN`, `META_PIXEL_ID`، اختياري `META_TEST_EVENT_CODE` | Events Manager › Settings › Conversions API |
| الحماية | `ALLOWED_ORIGINS` = رابط موقعكِ (مثال `https://ronaq.dz`) | يمنع المواقع الأخرى من استعمال واجهة الطلبات |

بعد إضافة المفاتيح، في لوحة التحكم › **التوصيل**:

1. اضغطي «اختبار الاتصال».
2. اضغطي «مزامنة المكاتب والبلديات»، وهي ضرورية لـ Yalidine حتى تُكتب أسماء البلديات كما تقبلها.
3. اختاري «الشركة الافتراضية».

## 4. النشر على الإنترنت

1. **الخادم:**
   ```bash
   npx convex deploy
   ```
   ينشئ نسخة الإنتاج. أضيفي متغيرات البيئة لها أيضاً (نسخة Production في لوحة Convex)، وأعيدي `seed` و `createOwner` بإضافة `--prod`.
2. **الموقع على Vercel:** ارفعي المشروع إلى GitHub، ثم في Vercel استوردي المستودع. اتركي **Root Directory** فارغاً، واختاري Framework **Vite**. الإعدادات الباقية في `vercel.json`، وكل `git push` ينشر نسخة جديدة تلقائياً.

   بعدها اربطي اسم نطاقكِ، وضعيه في `ALLOWED_ORIGINS` في Convex.

## 5. العمل اليومي

**المسار:** جديد ← مؤكد / لا يرد ← قيد التحضير ← مُرسل ← مُسلَّم / مرتجع.

- **المؤكِّدة** تتصل بالزبونة أو ترسل لها رسالة WhatsApp جاهزة، ثم تضغط «تأكيد» أو «لا يرد» (يُحسب عدد المحاولات، مع موعد لإعادة الاتصال). ويمكنها تعديل الطلب قبل الإرسال.
- **اللوجستيك** تختار الشركة، ومكتب الاستلام إن كان التوصيل للمكتب، ثم تضغط «إرسال إلى…». يُنشأ الطرد مباشرة عند الشركة مع رقم التتبع والملصق. ويمكن إرسال عدة طلبات دفعة واحدة من القائمة.
- **كل 30 دقيقة** تُجلب حالات الطرود تلقائياً، فيتحول الطلب إلى «مُسلَّم» أو «مرتجع» وحده.
- **المخزون** ينقص عند التأكيد، ويعود عند الإلغاء أو الإرجاع، مع سجل لكل حركة.
- **Meta** تستقبل ثلاثة أحداث:
  - `Lead` عند الطلب، من المتصفح والخادم معاً وبدون تكرار.
  - `Purchase` عند **التأكيد الحقيقي**.
  - `OrderDelivered` عند **التسليم**.

  هكذا يتعلّم الإعلان من المبيعات الحقيقية.
- **الطلبات المتروكة:** كل من كتبت رقماً صحيحاً ولم تُكمل. يمكنكِ الاتصال بها، أو مراسلتها عبر WhatsApp، أو «إنشاء طلب» لها مباشرة.
- **الزبائن:** وسوم تلقائية (وفية، مخاطرة، لا ترد غالباً) ووسوم يدوية، مع إمكانية الحظر.

**الأدوار:**

| الدور | الصلاحيات |
|---|---|
| المالك | كل شيء |
| المدير | كل شيء عدا الفريق |
| المؤكِّدة | الطلبات والتأكيد |
| اللوجستيك | الإرسال والمخزون |

## 6. ملاحظات مهمة

- **69 ولاية (تقسيم 2026):** الزبونة تختار ولايتها الجديدة (مثل بريكة 60)، وعند الإرسال تُحوَّل تلقائياً إلى الولاية الأم التي تعتمدها شركات التوصيل (باتنة 05).
- **NOEST:** الطرد يُنشأ ثم يُصادَق عليه تلقائياً. بدون المصادقة لا تستلمه NOEST.
- **ZR Express** لا تخدم إليزي، تندوف، برج باجي مختار وجانت. ملصقها رابط مؤقت يُجدَّد عند كل ضغطة.
- **إلغاء الطرد** ممكن فقط قبل أن تستلمه الشركة (Yalidine: «En préparation»).
- **NOEST** لا تنشر قائمة رسمية لحالاتها. قراءة «مُسلَّم / مرتجع» تعتمد على نص الحدث، والحالة الخام تظهر دائماً في الطلب للتأكد.
- **Yalidine:** إذا رفضت الاتصال من خوادم Convex، أضيفي `YALIDINE_BASE_URL` (رابط وسيط) و `YALIDINE_PROXY_SECRET`.
- **المنطق المأخوذ عن CodFlow:** طريقة الربط بشركات التوصيل (أسماء الحقول، الحالات، الخطوات) مأخوذة عن محوّلات مشروع CodFlow المجرّبة في الإنتاج (رخصة Apache-2.0).
- **بيانات الولايات والبلديات** من مشروع dzship (رخصة CC0).

## 7. السرعة على إنترنت وهواتف الجزائر

- **حجم الصفحة الأولى:** حوالي 85 KB. صورة المنتج تُضغط تلقائياً عند رفعها (1200 px بصيغة WebP).
- **النتيجة في Lighthouse:** 99 على الهاتف، و91 عند محاكاة 3G بطيء مع هاتف ضعيف.
- **الزيارة الثانية فورية:** المنتجات والملفات تُحفظ على الهاتف، وتتحدّث في الخلفية.
- **البلديات:** تُحمَّل فقط للولاية المختارة (1 إلى 2 KB). إن ضعفت الشبكة، تكتب الزبونة البلدية يدوياً.
- **إرسال الطلب:** يعاد تلقائياً مرة واحدة إذا انقطع الاتصال، بدون تكرار الطلب.
- **الوضع الخفيف:** على 2G/3G، أو مع «توفير البيانات»، أو على هاتف بذاكرة 2 GB أو أقل، تتوقف الحركات الزخرفية تلقائياً.
- **بعد كل تعديل:** يكفي `git push`، فـ Vercel يبني الموقع من جديد ويغيّر رقم نسخة التخزين تلقائياً حتى يرى الزبائن التحديث.

## 8. للمطوّر

```bash
npm test            # اختبارات الخادم (convex-test): الطلب، التأكيد، المخزون، الحدود، الإرسال لـ Yalidine، الصلاحيات، تسجيل الدخول
npm run typecheck
```

- **واجهة المتجر:** `POST /api/order` تعيد حساب الأسعار والتوصيل في الخادم ولا تثق بالمتصفح. تمنع الطلب المكرر وتحدّ عدد الطلبات لكل رقم ولكل IP، وتحتوي حقلاً مخفياً ضد الروبوتات.
- **لوحة التحكم:** محدّثة لحظياً عبر `ConvexClient`. طلب جديد يُظهر تنبيهاً وصوتاً.
- **مجلد `convex/_generated`:** يُعاد إنشاؤه تلقائياً عند `npx convex dev`.
